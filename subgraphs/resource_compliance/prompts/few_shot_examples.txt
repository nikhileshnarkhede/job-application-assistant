# Resume Compliance Evaluation - 20 Examples

These examples demonstrate proper evaluation of resume elements.

---

## Example Set 1: Personal Information Evaluation

### Good Example (PASS)
```
Header: John Smith | john.smith@gmail.com | (555) 123-4567 | linkedin.com/in/johnsmith

Evaluation:
- [PASS] Located at the top of the page | Clean, prominent placement
- [PASS] First and last name in larger font | Name stands out appropriately
- [PASS] One phone number included | Professional format
- [PASS] One professional email address | Gmail is acceptable
- [PASS] LinkedIn URL included | Active profile linked
- [PASS] Does not take excessive space | Single line header
```

### Bad Example (FAIL)
```
Header: Johnny | johnny123@yahoo.com | Home: 555-1234, Cell: 555-5678, Work: 555-9999

Evaluation:
- [FAIL] Located at the top of the page | Name only, incomplete
- [FAIL] First and last name | Missing last name
- [FAIL] One phone number included | Three numbers is confusing
- [FAIL] Professional email address | Unprofessional format
- [FAIL] LinkedIn URL included | Missing
- [PASS] Does not take excessive space | Compact but incomplete
```

## Example Set 3: Experience Bullets Evaluation

### Excellent Bullets (Score: 4)
```
- Engineered distributed data pipeline using Apache Spark, processing 50TB daily with 99.9% uptime
- Led team of 5 engineers to deliver ML recommendation system, increasing user engagement by 35%
- Reduced model inference latency from 200ms to 45ms through optimization and caching strategies

Evaluation:
- [PASS] Bullets start with action verbs | Engineered, Led, Reduced
- [PASS] Action verbs in appropriate tense | Past tense for past role
- [PASS] Achievements quantified | 50TB, 99.9%, 5 engineers, 35%, 200ms to 45ms
- [PASS] No passive phrases | Active voice throughout
```

### Poor Bullets (Score: 1)
```
- I was responsible for data pipeline development
- Worked with team on ML projects
- Helped to improve system performance

Evaluation:
- [FAIL] Bullets start with action verbs | Starts with "I was", "Worked", "Helped"
- [FAIL] Action verbs in appropriate tense | Inconsistent tense
- [FAIL] Achievements quantified | No metrics or numbers
- [FAIL] No passive phrases | "Responsible for", "Worked with"
```

## Example Set 5: Format Evaluation

### Excellent Format (Score: 4)
```
Format Assessment:
- Page length: 1 page, appropriately filled
- Margins: 0.75 inches on all sides
- Font: 11pt Arial, consistent throughout
- Sections: Clearly labeled with bold headers
- White space: Balanced, easy to scan
- No graphics, tables, or images

RUBRIC: FORMAT: 4 | Professional appearance, easy to scan, no errors. Ready for ATS and human review.
```

### Poor Format (Score: 1)
```
Format Assessment:
- Page length: 3 pages for entry-level candidate
- Margins: Inconsistent (0.3" left, 1.5" right)
- Font: Mixed fonts (Times, Arial, Comic Sans)
- Sections: No clear headers
- White space: Overcrowded, hard to read
- Contains: Photo, table layout, text boxes

RUBRIC: FORMAT: 1 | Significant formatting issues. Would likely fail ATS parsing and be difficult for recruiters to scan.
```

## Example Set 6: Pronoun Detection

### No Pronouns (PASS)
```
Text: "Developed machine learning models for prediction. Led team of engineers. Achieved 40% improvement."

- [PASS] No personal pronouns | Clean, professional tone
```

### Contains Pronouns (FAIL)
```
Text: "I developed ML models that helped my team. We achieved great results together."

- [FAIL] No personal pronouns | Contains: "I", "my", "We"
Notes: Remove all instances of I, me, my, we, our. Rewrite as: "Developed ML models. Achieved results collaboratively."
```

## Example Set 11-20: Common Issues and How to Evaluate

### 11. Missing Location in Experience
```
- [FAIL] Employer with city and state | "Google" - Missing location
Fix: Add "Google, Mountain View, CA"
```

### 12. Unclear Job Title
```
- [FAIL] Position title clear | "Various responsibilities" - Not a title
Fix: Use actual title: "Software Engineer" or "Data Analyst"
```

### 13. Irrelevant High School
```
- [FAIL] High school removed | Listed despite being 5 years post-college
Fix: Remove high school education for candidates 2+ years in college
```

### 14. Too Many Pages
```
- [FAIL] Appropriate length | 4 pages for entry-level
Fix: Condense to 1 page, focus on relevant experience only
```

### 15. Template-Based Design
```
- [FAIL] Original design | Obvious Word template with shading
Fix: Create clean, custom layout without template elements
```

### 16. Obvious Skills Listed
```
- [FAIL] No obvious skills | Lists "Microsoft Word, Email, Internet"
Fix: Remove basic skills everyone has. Focus on specialized tools.
```

### 17. Passive Voice Throughout
```
- [FAIL] No passive phrases | "Was responsible for", "Worked on"
Fix: "Led", "Developed", "Managed" - Active verbs only
```

### 18. No Certifications When Relevant
```
- [FAIL] Certifications if applicable | AWS role but no AWS certs
Fix: Add AWS certifications or note "In progress"
```

### 19. Inconsistent Formatting
```
- [FAIL] Consistent font and spacing | Mixed 10pt, 11pt, 12pt
Fix: Standardize to single font size (10-12pt)
```

### 20. Missing Keywords
```
- [FAIL] Keyword-rich | Generic descriptions, no industry terms
Fix: Add relevant technical terms from job descriptions
```

---

## Key Evaluation Principles

1. **Be Consistent**: Same standard for all sections
2. **Be Specific**: Cite exact issues, not vague concerns
3. **Be Constructive**: Every FAIL includes how to fix
4. **Be Prioritized**: Critical issues flagged as [CRITICAL]
5. **Be Fair**: Acknowledge strengths alongside improvements
